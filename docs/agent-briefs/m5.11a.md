No production credentials, data or writes: anything that needs production (real access lists, real audit-log samples) becomes a reviewed runbook script the owner runs.

Scope (each fully tested):
- **Control mapping**: SOC 2 Trust Services Criteria CC1–CC9 (plus A1 availability and C1 confidentiality) mapped to repo evidence (ADRs, runbooks, CI jobs, gates, policies, tests) in a machine-readable file (e.g. `compliance/controls.yaml`) with a check that every control has at least one evidence source and every referenced path exists.
- **Scheduled evidence exports** (a scheduled GitHub Actions workflow, read-only `GITHUB_TOKEN`): CI run history and gate results, branch protection settings, PR reviews and approvals (change management: who reviewed, which labels needed owner approval), repository access lists, and **audit-log samples from the seeded CI database** (never production); a `tools/compliance` script builds a dated, checksummed evidence bundle as a workflow artifact.
- **Redaction and leak gate**: the bundle is scanned with gitleaks and a PII check (emails other than `*.test`, tokens, keys, IPs) before upload; any hit fails the job; planted canaries prove the gate fails.
- **VPAT (WCAG 2.2 AA) draft** generated from the axe results and keyboard suites of the e2e shards (criterion → status → evidence → remarks), marked draft for the owner's sign-off.
- **Policy drafts** for the owner's review (information security, access control, change management, incident response, vendor management, data retention per D11, business continuity), linked to existing runbooks; each marked "draft, pending owner".
- A production evidence runbook (`docs/runbooks/`) for the steps only the owner can run (real access reviews, Doppler and hosting access lists), and `docs/owner-inbox.md` entries for Vanta, auditor, pen test, VPAT sign-off and DPF.
- No UI, no tenant tables, no `/v1` changes; any read of audit data uses the existing audited paths (`platform_reader` only from the worker/tooling side, never from apps/web).

Tests: unit (control-mapping completeness and path existence, redaction rules, VPAT generation from a fixture axe report), integration (**the evidence bundle builds from a CI run with no manual step**; planted secret and customer-data canaries make the job fail; **no secrets or customer data in the bundle**; audit-log samples come only from seeded orgs), and a dry run of the scheduled workflow via `workflow_dispatch` documented in the PR. No e2e UI; the VPAT draft consumes the existing e2e (keyboard, axe, Arabic RTL) results rather than adding new ones.
