## Scope (each fully tested)
- **APNs adapter:** HTTP/2 with `.p8` token auth, the topic set to the bundle ID, and the sandbox or production host chosen per token.
- **FCM adapter:** HTTP v1 with a service account.
- **Wiring:** both go behind `PushTransport` through `routedPushTransport` and `liveTransports`, with modes from `providerMode()` and env names that follow `.env.example`'s pattern. Use a fake in dev and CI.
- **Provider responses:**
  - An unregistered or invalid token sets `disabled_at`, and a re-registration re-enables it.
  - 429 and 5xx retry with backoff.
  - A collapse ID per ticket, so updates replace each other.
- **Devices:**
  - `POST /v1/me/devices` (platform, token, app id, app version, locale, time zone) and `DELETE /v1/me/devices/{token}`.
  - Rows are stored per org where the person has orders or tickets, keyed by `email_norm` with `source: app`, like `registerOrderPushCommand`.
  - When the person later buys from a new org, an outbox consumer adds rows there. Sign-out deletes them.
- **Notification types (P7-8)** on the existing templates, in all 13 locales:
  - order confirmed, ticket received, transfer accepted or cancelled, event changed or cancelled
  - reminders 24 h and 2 h before start, in the event's time zone
  - per-org and per-type preferences respected
  - a deep-link payload (`/tickets/{id}`, `/orders/{id}`, `/events/{slug}`)
- **Lock-screen text:** the event name and what changed only.

## Acceptance
- A token the provider reports as unregistered is never sent to again until it is re-registered.
- A phone never receives a push from an org where its owner has no order or ticket (isolation test).
- No push title or body contains an email, phone number, amount or ticket code (a test over every template in every locale).
- Each reminder fires once per ticket, in the event's time zone, including across a DST change.
