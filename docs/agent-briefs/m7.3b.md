# Task: M7.3B — Tickets (branch agent/m7.3b)
Read `common.md` (including its "Don't stall" section) and `mobile-common.md` (its Base section and "Wave 3"). Then read `docs/plans/mobile.md` (row M7.3b and decision P7-7), ADR 0011 (QR codes), and the code:
- `packages/api-v1/src/routes/me.ts` and `src/me/*` (M7.2b: my tickets, orders, transfers, wallet link, claims)
- `packages/mobile-core` (the client, query cache, theme with tenant colours, `ROUTES`)

- the web's My tickets and ticket page for behaviour parity (`apps/web/src/app/[locale]/my-tickets`)

**Base:** `origin/main` after Wave 2 (see `mobile-common.md`).

## Scope (each fully tested)
- **My tickets** (the Tickets tab): upcoming and past, grouped by event, with keyset paging and pull to refresh; the empty state links to Discover.
- **Ticket detail** (`/tickets/[id]`):
  - the QR code at full screen brightness (restored on leave), the short code, holder name, ticket type, seat, entrance and zones
  - the event time in the event's time zone, the venue, the organizer's branding through the theme (with the contrast fallback)
  - add to calendar (`expo-calendar`, with its permission string) and directions (the maps app)
  - Add to Apple Wallet / Save to Google Wallet through the M7.2b link (the fake until the owner's accounts)
- **Offline:** tickets open with the network off after one sync, from the encrypted cache; the cache is cleared at sign-out. Show when the data was last synced.
- **Transfer:** start (recipient name and email, confirm), cancel a pending transfer, and the transfer-fee case that opens the web link in a secure browser session. Respect `transfersAllowed` and the cutoff the API returns.
- **Refund requests:** from the order panel the API returns, following the order's policy.
- **Claims** (`/claim/[token]`): show what is being claimed, require sign-in, then claim; an email mismatch explains which address the ticket was sent to.
- **Ticket links** (`/tickets/link/[token]`): resolve to the ticket after sign-in.

## Acceptance
- With the network off after one sync, My tickets and every ticket's QR open; signing out removes them.
- A transferred ticket leaves the sender's list after refresh; a pending transfer can be cancelled.
- The QR has a spoken description ("Ticket QR code for <event>"), and the short code is readable by screen readers.
- Component tests for every state (loading, empty, error, offline, past event, transferred, refunded); Arabic RTL. Maestro flows: open a ticket offline, transfer and cancel, claim from a link.
