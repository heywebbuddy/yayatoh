**Base:** the build branch, plus every merge batch not yet landed (`git merge --no-edit origin/merge/next-3i`, then `origin/merge/next-3j`, for each that exists and is not already an ancestor), so your changes cover the newest screens. The UX principles in the plan are the acceptance bar for every screen you touch: design tokens only, logical CSS, 13 locales with Arabic RTL, keyboard and screen reader, 24 px targets, light and dark. Never weaken an e2e assertion: move selectors to roles or labels where markup changes.

The other UX increments build on your components: push the components first (in the first hour or two) with a short note in `packages/ui/README.md`.

## Scope (each fully tested)
- New `@yayatoh/ui` components (headless logic you write or a small, well-maintained dependency; no heavy UI framework):
  - **Select** (single choice, styled listbox): trigger with `appearance: none`; **our own chevron icon inside the field, vertically centred, 16 px, `--text-muted`, 12 px inline-end padding**, text padded so it never runs under the chevron, chevron rotates 180° when open, mirrored in RTL, never clipped by the radius; the open list is a floating panel in our theme (never the OS popup) with a selected tick, hover/active, type-ahead, Home/End, PageUp/PageDown, max height with scroll, auto search above 8 options, long labels wrap. Works inside forms (hidden input or `name`, so server actions keep working) and supports `required`, `disabled`, error and hint like `Input`.
  - **Combobox**: searchable, async options, multi-select with chips, "create new" option hook.
  - **DatePicker, DateTimePicker, TimePicker**: our calendar popover, typed entry still allowed, locale-aware formats (13 locales, Arabic digits and RTL), min/max, and **event-time-zone aware** (value stored as timestamptz; the zone shown next to the field).
  - **TimeZonePicker** (IANA, searchable, grouped by region, shows the current offset) and **CurrencyPicker** (ISO 4217, searchable, symbol and name).
- **Replace every native `<select>` and `type="date|time|datetime-local"` input** in `apps/web` and `apps/admin` (~150) with these components; keep every form's submitted values identical.
- A **check-modules gate** (`no-native-select`): raw `<select>` and native date/time inputs are forbidden outside `packages/ui`; a canary proves the gate fails on a violation.
- `/dev/design` shows every component in every state, both themes, LTR and RTL.

## Acceptance
- The gate finds **zero** native selects or date/time inputs outside the UI kit.
- The chevron is inside the field, centred and padded at all three sizes, in LTR and RTL (visual snapshot test).
- WAI-ARIA listbox/combobox/grid-date patterns pass keyboard and screen-reader tests; axe clean in both themes.
- Every replaced form submits the same values as before (existing e2e still pass with role-based selectors).
- E2E: each component in /dev/design; three representative forms (create event, venue, settings) end to end; keyboard only, axe in both themes, RTL. Attach before/after screenshots (light and dark, 1280 and 390 px) of the main screens to your report (commit them under `docs/ux/screenshots/u1/`).
