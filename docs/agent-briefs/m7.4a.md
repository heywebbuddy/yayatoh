Read `common.md` (including its "Don't stall" section) and `mobile-common.md` (its Base section and "Wave 3"). Then read `docs/plans/mobile.md` (row M7.4a and decision P7-6), ADR 0011, and the code:

**Base:** `origin/main` after Wave 2 (see `mobile-common.md`). M7.4b and M7.4c stack on you: push `src/device/` early.

## Scope (each fully tested)
- **Device session** (`apps/staff/src/device/`, push this first): the `yyd_` token in secure storage; `useDevice()` returns `{ status: 'unenrolled' | 'enrolled' | 'revoked' | 'wiped', deviceId, eventId, checkpointId, token }` plus `enrol(link)`, `selectCheckpoint(id)` and `forget()`; an `onWipe(callback)` hook that M7.4b uses to delete the manifest database.
- **Enrolment:** scan the enrolment QR with the camera (camera permission string, Staff only) or open its universal link; the key comes only from the URL fragment and never reaches logs.
- **Event and checkpoint picker** for the enrolled event.
- **Heartbeat** every 30 s while scanning: battery, queue depth (from M7.4b's outbox, 0 until then), clock offset. A 401 means revoked or wiped: wipe local data within one heartbeat and return to enrolment.
- **Version gate:** never show the required-update screen inside the event window (24 h before start to 2 h after end), through `suppressRequiredUpdate`.
- **Organizer sign-in** with TOTP (the M7.2a helpers) for the read-only event-day view (M7.4c builds the view).
- **Exhibitor sign-in** by email code into a portal bearer session for lead retrieval (M7.4c builds the screens).

## Acceptance
- A wiped device erases its token and data within one heartbeat; a revoked device returns to enrolment.
- The enrolment key never appears in a request URL, a log or a crash report (tests on the redaction).
- No required-update screen inside an event window, even when the server says the version is below minimum.
- Component tests for every state; Arabic RTL; iPad layout. Maestro flows: enrol by link, pick a checkpoint, remote wipe.
