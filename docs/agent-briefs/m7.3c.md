## Scope (each fully tested)
- **Discover** (the Discover tab): search with text, category, date range and "near me" (location permission only when the person taps it, with its permission string); soonest or nearest first; keyset paging.
- **Event page** (`/events/[slug]` and `/e/[code]`): details, dates in the event's time zone, venue and map link, organizer branding through the theme, and ticket types with prices and availability.
- **Ticket selection** with the web's rules (quantities, limits, sold out, sales windows, promo code).
- **Checkout:** call the M7.2f route with an idempotency key; on `pay`, open the payment URL in a secure browser session (`expo-web-browser` auth session) that returns to the app; on `paid`, go straight to the confirmation; on `web`, explain why and open the web checkout. A return link opens the order confirmation; a cancel link returns to the event with the cart kept.
- **Virtual and livestream tickets:** shown with "Buy on the web", never purchasable in the app (P7-7, App Review 3.1.3).
- **Orders** (`/orders/[id]` and a list reachable from Account → Orders): lines, totals in the event's currency, refund-request status.

## Acceptance
- A fake-provider purchase ends on the order confirmation, and its tickets appear in My tickets.
- Cancelling payment returns to the event with the selection intact; a replayed checkout (same key) never makes a second order.
- No virtual or livestream ticket can be bought in the app; carts the API sends to the web open the web checkout.
- Component tests for every state; Arabic RTL; prices formatted per locale and currency. Maestro flows: search and buy with the fake provider, cancel payment, a virtual ticket shows "Buy on the web".
