## Scope (each fully tested where it's code)
- **Store listings** for Yayatoh and Yayatoh Staff in `apps/<app>/store/` (EAS metadata format, `store.config.json`): name, subtitle, keywords, description, promotional text, support and marketing URLs (from `.env.example` names), categories and age rating. English first, then the 12 other locales; App Store and Play length limits checked by a test.
- **Screenshots:** a deterministic screenshot plan (Maestro flows that land on each listed screen with seeded data, light and dark, phone and iPad for Staff) and the device sizes each store needs. The device pass runs them; the output folder layout is documented.
- **Privacy:** App Store privacy labels and Play Data safety derived from the SDKs actually used, written as data (`apps/<app>/store/privacy.json`), with a script `pnpm --filter <app> privacy:check` that fails when a dependency that collects data is added or removed without updating the labels.
- **Compliance answers:** export compliance (standard encryption only, `ITSAppUsesNonExemptEncryption`), the content rating questionnaire, and the App Review notes: no in-app purchase because tickets are physical services (3.1.3(e)), virtual tickets are not sold in the app, account deletion is in Account (5.1.1(v)), Sign in with Apple beside Google (4.8), and how a reviewer uses the Staff app.
- **Reviewer demo:** a seeded demo org and event with a reviewer attendee account (email code fixed in the fake mailer for that address only in non-production) and a Staff enrolment link, created by a script that is idempotent and refuses to run against production.
- **EAS:** `eas.json` submit profiles (TestFlight, Play internal, closed, production) using environment names only; EAS Update channels per profile with `fingerprint` runtime versions (P7-9).
- **Runbook** `docs/runbooks/mobile-release.md`: build, submit, phased release on Apple and staged rollout on Play, over-the-air fixes and when not to use them, the 72 h event freeze, minimum-version bumps (and never for Staff inside an event window), rollback, and the first-submission checklist for the owner's accounts.

## Acceptance
- The runbook alone gets each app built, submitted to the test tracks and rolled back (reviewed step by step against `eas.json` and the scripts).
- `privacy:check` passes, and fails when a data-collecting dependency is added without a label change (test).
- Every listing text is within each store's limits in all 13 locales (test); the reviewer demo script is idempotent and refuses production.
