## Scope (each fully tested)
- **The new `donations` module** (pick its tier per the module rules), with a MODULE.md.
- **Campaigns** with a goal (integer minor units, the event currency), per event.
- **Giving levels:** name, amount, optional description ("$1,000 funds a classroom").
- **A public, mobile-first giving page** per event, offering:
  - level buttons or an own amount (min/max)
  - one-off gifts
  - **cover the processing fee** (P4-10, off by default; it goes to the charity)
  - a **tribute** (in honor of / in memory of, with an optional note to a named recipient)
  - **how the donor's name appears** (full name, first name only, or anonymous; P4-13)
  - employer name (P4-17)
- **Payment:**
  - An order with a `donation` item, as a **direct charge on the connected account with application fee 0** (P4-9). This uses the existing funds-flow code paths and the fake provider in tests. Never call Stripe; never set `PAYMENTS_PROVIDER=stripe`.
  - Idempotency-Key on every side effect.
  - Orgs without a connected account see "Connect Stripe to accept gifts", and the public page is unavailable.
- **The Donations tab** replaces its placeholder:
  - campaigns, levels, totals, the gift list
  - donor names shown per consent
  - CSV export with step-up
- **Privacy:** amounts and tribute notes go in private columns. Public payloads never contain a donor's name unless the donor opted in.
- Out of scope: receipts and the charity profile (M4.8b), paddle raise (M4.8c), live screen (M4.8d), saved cards and pledges (M4.8e), matches (M4.8f).

## Acceptance
- A gift charges exactly the chosen amount plus the fee cover, on the connected account, with application fee 0 (assert on the fake provider's recorded charge).
- An unconnected org cannot open the page.
- Anonymous gifts never show a name in any public payload. Extend the leak crawler or canary.
- Webhook replay never double-counts.
- Isolation; impersonation and freeze coverage.
- E2E on all three projects:
  - give with a level, own amount, fee cover and tribute
  - an anonymous gift appears as "Anonymous" in host lists where shown
  - an unconnected org
  - keyboard only, axe, RTL
  - viewer denied the tab's write actions
