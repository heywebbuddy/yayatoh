Scope (each fully tested):

- **Grouping into parties** by a household column; rows without one become a party of one; a "plus one"/"guest of" marker creates a placeholder plus-one on the row's guest; the first named adult is the primary contact; M4.1a's limits (20 per party, per-event caps) apply and reject the whole party, never half of it.
- **Rejected rows** with reasons per row, downloadable as CSV (formula-injection safe); nothing is imported until the host confirms.
- Every created party and guest writes `rsvp_history` with source **`import`** and the batch id; running the same batch twice imports once (idempotency key per batch).
- **Privacy (P4-3)**: dietary, accessibility and address columns are sealed into `private_ciphertext` on import; staged raw rows holding them are sealed too and purged after import or expiry; never creates CRM contacts, consents or audience members; raw rows never reach logs or audit data.
- Large files run as a pg-boss job with progress; small ones inline.
- House rules: every write through `tenantCommand` (entitlement `guests`, permission `guests:write`, so co-hosts and planners can import on their events), allowlist serializers, every new text/jsonb/text[] column in `private-columns.ts`, fixture rows for both orgs in `createOrgFixture`, 13 locales + Arabic RTL, logical CSS, tokens only, strict CSP.
