# Task: M7.1A — Universal crypto and test vectors (branch agent/m7.1a)
Read `common.md` (including its "Don't stall" section) and `mobile-common.md`. Then read `docs/plans/mobile.md` (row M7.1a and the Hermes risk), ADR 0011, and the code:
- `packages/ticket-crypto/src/ticket-code.ts` (`verifyTicketCode`, `verifyStatement`) and `legacy.ts` (`legacyPayloadHash`)
- `packages/checkin-engine/src/offline.ts` (`lookupHash`, `offlineVerdict`) and the tests of both packages
- `packages/modules/ticketing/src/issue.ts` (server signing)
- `tools/check-modules/src/check.ts`
- the Scan PWA (`apps/web/src/scan/`)

**Base:** `origin/main` (see `mobile-common.md`).

Every door decision depends on this code, on the web today and in the Staff app later. Change how it computes, never what it decides.

## Scope (each fully tested)
- **Remove `crypto.subtle` from the universal packages.** Ed25519 verification moves to `@noble/curves` and SHA-256 digests to `@noble/hashes`. Add both to the pnpm catalog at exact versions. Keep the exported functions' names and signatures (async stays async), so no caller changes. Server signing in `issue.ts` may stay on WebCrypto.
- **Fixed test vectors**, committed as JSON (`packages/ticket-crypto/vectors/`, `packages/checkin-engine/vectors/`). A script with fixed seeds generates them (e.g. `pnpm --filter @yayatoh/ticket-crypto vectors:write`); a test asserts the code reproduces every file exactly, so they can never change silently. Cover:
  - valid codes for several key ids
  - a tampered signature, an unknown key id and an unknown version
  - a superseded `rev`
  - every legacy payload form
  - every ADR 0011 verdict row, including the provisional-admit policy and first-wins with clock offset
  - lookup hashes for email and E.164 phone normalization
- **check-modules:** universal packages may not reference `crypto.subtle`. Add a rule test.
- **Benchmark:** a Node script measuring verify and verdict time per code. Record the numbers in the spec; M7.4b repeats them on a phone.

## Acceptance
- Every vector passes in Vitest, and the Scan PWA's existing e2e specs pass unchanged on all three projects.
- A code issued by `issue.ts` verifies with the new verifier (integration test).
- A `crypto.subtle` use in a universal package fails `check:modules`.
- No change to any verdict: the existing `offline.test.ts` passes untouched.
