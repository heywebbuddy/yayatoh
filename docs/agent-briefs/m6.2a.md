**Base:** the build branch, plus the newest merge branch that exists (`git merge origin/merge/next-3h`, else 3g). Phase 6 is built **behind flags** and an entitlement key (P6-13): anything that charges money or talks to a real third party goes through a port with a **fake in dev and CI**. No real vendor accounts, keys or network calls; `.env.example` names only.

## Scope (each fully tested)
- An **`AnalyticsWarehouse` port** in front of the M3.1a sink (P6-2), with two adapters:
  - **Postgres rollups** (default): partitioned per org and day, refreshed from the outbox; `org_id` leads every index; FORCE RLS.
  - **Tinybird**: an HTTP adapter (datasource append + pipe queries) with a fake in CI that records calls and serves fixture results. Selected by `ANALYTICS_WAREHOUSE=postgres|tinybird`; Postgres is the default everywhere.
- Ingest from the outbox through a dedicated subscriber; idempotent by event id; versioned event schemas.
- A **backfill job** (pg-boss) that rebuilds an org's rollups from source tables in pages; resumable; rate-limited.
- **Cross-event dashboards** (org level): revenue, tickets, registrations, check-ins, no-shows, top events, by day/week/month in the **org time zone**; currency kept separate (never summed across currencies).
- Every query is scoped by org at the port: the adapter receives `ctx`, never a raw org id from the caller.
- Wire allowlist serializers for every dashboard payload; money visible only with finance permission.

## Acceptance
- **Isolation through the warehouse:** two orgs' data never mix, on both adapters (the Tinybird fake asserts every query carries the org filter).
- Dashboards match Postgres source totals **to the cent** on the fixture orgs.
- Replaying the outbox twice writes once; a backfill after live ingest changes nothing.
- E2E: org dashboards (filters, period switch, empty state), keyboard only, axe in both themes, RTL; a finance-less role sees no money.
