## Scope (each fully tested)
- **Self-serve API keys per org**: name, scopes (read/write per resource group from resources.ts), expiry, last used, created by.
  - Shown once on creation, stored hashed.
  - Rotate (overlap window) and revoke.
  - Step-up to create.
  - Audit every use summary (daily counts) and every create/revoke.
- **Rate limits per entitlement** (`api_access` plan quotas, placeholders per P6-13) with `RateLimit-*` headers and 429s.
- **Usage page**: requests per day and per key, errors.
- **Sandbox orgs**: create a sandbox linked to your org.
  - Seeded data.
  - Fake payments forced (never a real provider, enforced in the payments module).
  - A clear "SANDBOX" banner.
  - Can't publish to the marketplace.
  - Deletable.
- `/v1` stays additive: oasdiff and Spectral clean; SDK regenerated.

## Acceptance
- A key can't exceed its scopes or its org (generated /v1 tests).
- A revoked key fails on the next request.
- A sandbox org can never take real money (a test with PAYMENTS_PROVIDER forced on).
- Rate-limit headers are correct.
- Isolation.
- E2E: create, use (via request), rotate and revoke a key; create a sandbox; keyboard only, axe, RTL; viewer can't create keys.
