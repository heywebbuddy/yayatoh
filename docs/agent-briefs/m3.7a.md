# Task: M3.7a — automations and journeys (branch agent/m3.7a)

Read `docs/plans/phase-3.md` (approved; Wave C), roadmap M3.7, the existing scheduled sends / reminder planning / reschedule-on-date-change / send de-duplication code, `replayed` events from the migration (M2.2c), notifications and the policy gate (M3.5a/b), surveys (M3.9a), the alert engine (M3.2b: "automation failures" rule), pg-boss in `apps/worker`.

Scope (each fully tested):
- **Journeys**: an org defines a journey for an event (or series): trigger + ordered steps; each step = wait (relative to trigger or to event start/end in the event timezone) + action (send email/SMS/WhatsApp/push template, add label, survey invite) + optional condition (checked in, has seat, answered survey).
- **Triggers**: purchase (order paid), check-in, time relative to the event. Leave an extension point for RSVP (M4.1d).
- **`scheduled_actions`** table (tenant table) with pg-boss execution; idempotency key per journey+step+person so retries never duplicate; **`replayed` events never trigger** journeys.
- **Vision journey template**: purchase → confirmation; T−7 d reminder; T−24 h SMS/WhatsApp; event-day push; post-event survey.
- **Cancellation hooks** (order refunded/cancelled, event cancelled → pending steps cancelled); **reschedule on date change** (pending steps move; past steps don't re-send).
- **Run history** per journey and per person; **failure alerts** into the M3.2b engine.
- Builder UI in the organizer console: list, create from template, edit steps (keyboard, no drag required), enable/disable, run history. 13 locales, Arabic RTL, strict CSP.

Tests: unit (offset maths across DST in the event timezone, condition evaluation), integration with a fake clock: **time-travel test sends exactly 5 messages at the right offsets**; a date change reschedules pending steps; retries never duplicate; `replayed` events never trigger; refund cancels pending steps; failure raises an alert; isolation. e2e with keyboard, axe and Arabic RTL: create the vision journey from the template, enable it, buy a ticket, see the confirmation (Mailpit) and the scheduled steps in run history; viewer read-only.
