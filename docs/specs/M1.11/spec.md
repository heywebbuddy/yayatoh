# M1.11 — Marketplace, tenant sites and SEO

Roadmap: M1.11 ("`yayatoh.com`: home, listings, event page, `/o/{slug}`, venues, blog, pages. Tenant sites. The `public_listings` projection; canonical rules (§4.2). JSON-LD; sitemaps, robots and hreflang; per-org OG images. `legacy_redirects`; `/e/{short}`; legacy transactional URLs. Org-tagged caching. Embeddable ticket widget."). Roadmap §3.3 (marketplace isolation), §4.2 (hosts and canonical URLs), §4.4 (per-org OG images), §7.7 (SEO and URL continuity), §1 "Known defects to fix", owner decision D13 (marketplace defaults). Delivered in three increments. New module `@yayatoh/marketplace` (tier 6, schema `marketplace`); one migration.

## M1.11a — public listings, marketplace and tenant sites (done)
- **Projection** `marketplace.public_listings` (tenant table, RLS). One row per event that is `public`, published or postponed, of an active or limited org. Allowlisted columns only: slug, name, tagline, profile, status, times and timezone, venue, city, ISO country, currency, the all-in price range of the public ticket types, the org's slug and name, `on_marketplace`, `canonical_host`, lastmod. No PII, no ids leave through `ListingDto`.
  - Written only by the **`marketplace.listings` projector** (outbox subscriber, registered in the worker): `event.*@1` (created, updated, published, unpublished, postponed, rescheduled, cancelled, completed, archived), `ticket_type.created|updated|archived@1`, `organization.updated@1`, `domain.activated|removed|primary_changed@1`. Each event **rebuilds the row from its sources** in the org's own transaction (idempotent; a replay converges; `processed_events` dedupes). Unpublish, cancel, complete and archive delete the row.
  - New events emitted by lower tiers (additive): `ticket_type.updated@1`, `ticket_type.archived@1` (ticketing), `domain.primary_changed@1` (tenancy, when the primary site host changes by check, hand-back or switch).
  - `catchUpSubscriber(subscriber, orgId)` (platform) applies an org's unhandled events to one subscriber through `consumeEvent`; `catchUpListings(orgId)` uses it for the seed and e2e (no worker runs there) and as a deploy-time catch-up.
  - After each change the worker makes a signed call to `POST /api/internal/revalidate` (HMAC of the org id with `APP_TOKEN_SECRET`), which revalidates that org's cache tag and the marketplace's.
- **Site settings** `marketplace.site_settings` (one row per org; absent = defaults): `list_on_marketplace` (D13: **opt-in for new orgs**, default off), `tenant_site` (canonical rule 2), `embed_origins` (M1.11c). `marketplace.updateSiteSettings` (`org:update`) refreshes the org's own listings in the same transaction and emits `marketplace.site_settings_changed@1`. `marketplace.siteSettings` (`org:read`).
- **Marketplace rules:** `on_marketplace` = listable ∧ enrolled ∧ not a wedding (D13: weddings and private events are never listed). Tenant sites list all of the org's listings.
- **Cross-tenant reads** only through SECURITY DEFINER functions returning allowlisted columns (roadmap §3.3 "marketplace isolation"; the house pattern instead of the separate `public_reader`/`marketplace_writer` roles, see "Not yet"): `search_listings` (text, city, category, day range, free/paid, organizer, pagination with a window total; upcoming and ongoing only; LIKE wildcards escaped), `listing_cities`, `listing_by_slug`, `sitemap_listings(host)`. A tenant site reads its own rows under RLS.
- **Host routing** (`apps/web/src/proxy.ts`, Node runtime; `lib/hosts.ts`):
  - Host classes: *marketplace* (`MARKETPLACE_HOSTS`, default `yayatoh.com, www.yayatoh.com, yayatoh.localhost`), *app* (`APP_HOSTS`, default `app.yayatoh.com`), *dev* (localhost, `*.vercel.app`: marketplace and console together, never indexed), *tenant* (anything else).
  - A tenant host resolves through `tenancy.org_by_host` (`resolveHost`; in-process LRU, 30 s). Unknown host → 404. **A non-primary host 308s to the primary** (roadmap §4.2). `/` and `/events/{slug}` rewrite to `/[locale]/t/[orgId]/…`: the org is a **route param**, never a header. `/t/…` is not addressable from outside (404).
  - On the marketplace host `/o/{slug}` rewrites to the public organizer page (`/organizers/{slug}` 308s back to `/o/{slug}`); on dev hosts `/o/{slug}` stays the console.
- **Pages** (all 13 locales, Arabic RTL, tokens only, logical CSS):
  - Marketplace home `/` (hero, search, the next six upcoming events, "See all events") and **`/events`** (legacy path): a plain GET search form (works without JS, shareable URL; name/place/organizer, city, category, price free/paid, from/to dates), result count, cards (dates in the event's timezone, place, "Free / €12 / From $20 / Tickets soon", Postponed badge, organizer link), empty and "no match" states with "Clear filters", previous/next pagination that keeps the filters. Invalid parameters are dropped, never an error.
  - **Organizer page** `yayatoh.com/o/{slug}`: brand-kit banner, all its public events (enrolled or not), link to its tenant site.
  - **Tenant site** `{org host}/`: the org's upcoming events, paginated; `{org host}/events/{slug}` is the event page; another org's event there is a 404.
  - The public event page body moved to `components/public-event-view.tsx`, shared by the marketplace, tenant sites and the widget.
- **Console:** a "Public site" page (`/o/{org}/site`, nav item `publicSite`): the two listing switches and the widget (M1.11c). Viewers see it read-only (disabled controls, no Save; the command refuses them).
- **Org-tagged caching:** `apps/web/src/server/public-cache.ts` `publicCached(scope, parts, load, revive)` is the only way to cache a public read: the key starts with and the tag is `org:{id}` (or `marketplace` for the cross-tenant projection); TTL 30 s plus signed revalidation. **Cache guard:** `check-modules` rule `cache-scope` refuses `unstable_cache`, `'use cache'` and `cacheTag(` anywhere else in the apps (canary `unscoped-cache`); unit test that two orgs never share a key or tag; e2e that the same route on two tenant hosts never shows the other org.
- **Seed:** a third org, **Harbor Arts Collective** (`harbor-arts`, owner `lee@harbor.test`): tenant site on, enrolled, events in New York, Paris (EUR) and Lagos, free and paid, one postponed, one cancelled, and a monthly series (pagination). Lakeside is enrolled; Rosewood (weddings) is not.

## M1.11b — SEO (done)
- **Canonical** (roadmap §4.2): an event's canonical origin is its org's verified custom domain, else its tenant subdomain when the org runs a tenant site, else the marketplace apex (`yayatoh.com/events/{slug}`, all migrated events). The projection stores it (`canonical_host`); the apex copy and the tenant page both point there. Organizer pages are canonical at `yayatoh.com/o/{slug}`; filtered or paged `/events` views are `noindex`.
- **hreflang**: all 13 locales plus `x-default` (unprefixed English), absolute, on every public page (`lib/seo/urls.ts`).
- **robots.txt per host** (`/robots.txt` route): public hosts allow crawling except private areas and name their sitemap; the dashboard, localhost and previews disallow everything; unknown hosts 404; non-primary tenant hosts 308.
- **Sitemaps:** `/sitemap.xml` (index: one per locale, lastmod = latest listing change) and `/sitemaps/{locale}.xml` (URLs with `xhtml:link` hreflang alternates and real lastmod). Only public pages: the home, `/events`, organizer pages and events whose canonical home is that host.
- **`noindex`** on unlisted, cancelled and finished events (reachable, not indexed), on dev/app hosts and on the widget.
- **JSON-LD `Event`** (`lib/seo/jsonld.ts`): absolute `url` (canonical) and `image`, `location` as a `Place` with a `PostalAddress` and an **ISO 3166-1 country code** (the legacy page emitted an id), `eventStatus` Scheduled/Postponed/Cancelled, `organizer` with its `/o/{slug}` URL, `offers` from the public ticket types (all-in decimal price, currency, availability InStock/SoldOut/PreOrder). `<` is escaped inside the script. Validated in unit and e2e tests with `EventJsonLdSchema`.
- **OG images:** absolute `og:image` on every public page. `/api/og/event/{slug}`, `/api/og/org/{slug}` and `/api/og/home` (`next/og`, 1200×630) in the org's **brand-kit colour with the contrast-chosen text colour**, tokens otherwise.
- **Legacy URLs** (roadmap §7.7): `marketplace.legacy_redirects(host, source, match exact|prefix, target, status 301/302/307/308, hits, last_hit_at)`, owned by the org whose content the target is; `(host, source)` unique globally (like hostnames); `host` may be `*`. Written only by `marketplace.addLegacyRedirect`, which needs the new platform permission `platform:redirects.manage` (migration tooling; org roles never have it). The proxy looks rules up (exact host before `*`, exact before the longest segment prefix; the rest of the path and the query carry over; hits counted) through `marketplace.match_redirect`, cached 60 s per host and path. Seeded examples: root organizer URLs (`/lakeside-events`, `/harbor-arts` → `/o/{slug}`), a renamed event, a prefix rule.
- **`/lang/{code}`** sets the locale cookie and 302s back to the referring page in that locale (it returns 500 on the legacy site).

## M1.11c — embeddable ticket widget (done)
- **Snippet** (console "Public site" page, one per public event, copy button with a live "Copied."; the field is selectable by keyboard): an `<iframe src="{apex}/embed/{slug}" data-yayatoh-widget loading="lazy" title="Tickets: …">` plus `<script src="{apex}/widget.js" async>`.
- **Widget page** `/embed/{slug}` (all locales, RTL, `noindex`): the event name, dates, its passes with prices and availability, "Powered by" when visible, and **"Get tickets", which opens the event page's checkout in a new tab** (a top-level page: payment wallets and the buyer's cookies need it; third-party iframes lose both).
- **Allowed origins:** the organizer lists the websites allowed to show the widget (https only, plus `http://localhost` for testing; at most 10; normalized). The proxy sends `Content-Security-Policy: frame-ancestors 'self' <origins>` on every widget response (not cached, so a change applies at once); every other site gets an empty frame.
- **Auto-resize:** the widget posts `{type: 'yayatoh:resize', height}` only to its embedding origin and only when that origin is allowed; `widget.js` accepts messages only from its own origin and only for an iframe on the page that sent them.

## M1.11d — canary leak crawler and the noindex guard (done)
Roadmap §9 ("Canary leak test: `__CANARY_<field>__` values are seeded into every `@private` column, then all public routes, `/v1`, webhooks, manifests and exports are crawled. Any canary found fails the build") and M1.11 acceptance ("the canary crawler finds nothing"). No migration, no new message keys.

- **Column-privacy registry (module-owned).** Each module that owns tenant tables exports `privateColumns` (`src/private-columns.ts`, built with `columnPrivacy(schema, …)` from `@yayatoh/db`) declaring **every** text, jsonb and text[] column of its tables: `'public'` (may be shown publicly), `'vocab'` (a closed-set machine value), or private with a class — `secret()` (tokens, hashes, ciphertext, provider and bank account ids: never in any response), `personal()` (names, emails, phones, answers, messages), `internal()` (notes, reasons, flags, audit details, system data) or `holder()` (join links, private info, ticket and access codes, holders-only announcements). Optional `seed` shapes the canary for CHECKs (`email`, `phone`, `url`, `path`, `code`, `sealed`, `sealed-json`, `none` + `why`); optional `where` limits it to the rows that are private (e.g. holders-only announcements, direct-charge account ids). `packages/platform` declares the `platform` schema. `@yayatoh/testing/canary` composes them (`COLUMN_PRIVACY`).
  - **Why module-owned, not a list in `packages/testing`:** only the module may describe its own schema (a central list would couple the test package to every module's internals and turn each new table into a cross-module edit and merge conflict). The classification sits next to the schema it describes and is reviewed with it; `packages/testing` only composes the public exports.
  - **Coverage test** (`packages/testing/tests/column-privacy.test.ts`, unit, no database): reads the newest drizzle snapshot, so any tenant table added by any branch is seen at merge. A column that is not declared fails with the exact fix, e.g. ``events.speakers.bio (text) is neither private nor public. Add `bio: 'public' | 'vocab' | secret() | personal() | internal() | holder()` in packages/modules/events/src/private-columns.ts: under `speakers`.`` A new schema gets the whole snippet plus "add it to COLUMN_PRIVACY". Stale entries and seeds that don't fit the column type fail too. (Parallel M1.4e/f/g and M1.6e tables are caught this way when they merge.)
- **`canaryOrg({ admin, slug?, reuse? })`** (`@yayatoh/testing`): a separate org (the isolation suite's two orgs are untouched) built with `createOrgFixture` (published public event, passes, orders, attendees, seating, content, venue, series, messages, notifications, exports, …) plus a tenant site, an allowed widget origin, a holders-only announcement, a retired signing key sealed around a canary and a direct-charge order. Then every registered private column of every org row is overwritten with `__CANARY_<schema>.<table>.<column>__` (+ a stable per-row suffix), as the database owner with triggers off (audit, outbox and ledger rows are append-only for the app role). Emails, phones (`+1999555…`), URLs, paths and upper-case codes (`CANARY_<nn>_<n>`) are shaped to pass their CHECKs; sealed columns get the canary plaintext encrypted with the org's key. It then mints a fresh API key and door device token, generates the attendee, bookings, access-request and activity exports, and sends an announcement through the fake transports (outbound capture). Idempotent with `reuse` (the e2e database survives reruns).
- **Matcher and crawler** (`@yayatoh/testing/canary`, pure): `findCanaries` (tokens case-insensitively, phone and code canaries), surfaces `public` (no canary), `scoped` (the org's own key, exports, the door: only the columns its allowlist names, never a `secret`) and `outbound` (no `secret`/`internal`); `crawl()` is breadth-first over the start URLs' origins with a page cap, extracts links from HTML, sitemaps and robots.txt, scans the raw response (including the streamed RSC payload), the headers and the hydrated DOM, and fails listing every hit (URL, column, class) and every 5xx. Allowlists: `V1_ALLOW` (per `/v1` route, mirroring `resources.ts`), `DOOR_ALLOW`, `EXPORT_ALLOW`.
- **e2e** `apps/web/e2e/canary-crawl.spec.ts` (in the normal suite; the global setup runs `e2e/canary-setup.ts`; `pnpm test:canary` runs it alone): the marketplace home, `/events`, `/o/{slug}`, the event page (en + ar), seat finder and poster, unlock, the widget, series, venues, the legal page, robots, sitemaps, the Scan PWA manifest, and the tenant site — then every same-origin link (≈75 pages); `/v1/public`, `/v1/mobile/config`, the OpenAPI document and unauthenticated org and scanner routes (public); every `/v1` org route with the org's key (scoped, and checked live: the org does see its own buyers); the door's offline manifest (device token); the four export files and the outbound messages. RSS/ICS feeds do not exist yet; JSON-LD and OG tags are inside the crawled HTML.
- **Gate canaries:** unit tests plant leaks in a fake site (a locale page, a response header, a JSON-LD block reached only through the sitemap) and the crawl must list them; the e2e plants one through a Playwright route on a test-only host (`planted.canary.test`), so the real browser fetcher is proven too. Nothing is added to production code.
- **Findings:** no canary leaked. The noindex guard found a real defect: a **postponed event 404'd on its own tenant site** (its canonical home, listed in the site's sitemap) because the tenant ownership check used the checkout target, which excludes postponed events. Fixed in `components/public-event-view.tsx` (ownership from the page target), regression test in `noindex.spec.ts`.
- **noindex guard:** `robotsHeader(kind, path)` (`lib/seo/robots.ts`) — the proxy sends `X-Robots-Tag: noindex, nofollow` on every response of a never-indexed host (dashboard, localhost, `*.vercel.app` previews) and on every private page (console, checkout, secret-link pages, scanner, sign-in, the widget frame, unlock, message and unsubscribe links, account); public pages on public hosts send none. `/o/{slug}` is public on the marketplace only. `robotsMeta(kind, index)` is the single rule behind public page metadata. Unit tests over both builders; `apps/web/e2e/noindex.spec.ts` (production build) checks that every page of the marketplace and Harbor sitemaps returns 200 with no noindex header or meta, private pages on both public hosts send the header, the signed-in console does, and preview, localhost and dashboard hosts are noindex in header and meta (the e2e browser maps `*.vercel.app` and `app.yayatoh.com` to the test server).

- **Gate (M1.11d):** `pnpm verify` green (unit 672, integration 511); whole web e2e suite 810 passed, 30 skipped, 0 failed.

## Not yet / Later
- **Canary crawl, later surfaces:** outbound webhooks (M6.3; the crawler's `outbound` surface takes the fake webhook sender's payloads when it exists), the `/api/v2` facade (frozen, not built), RSS/ICS feeds (none yet), and global identity tables (`auth.users`; not tenant tables, so outside the registry). Signed-in buyer and holder pages (my tickets, order manage links) are not crawled: their tokens are secret and the fixture seals them.
- **Venues directory (M1.4c) and `/e/{short}` (M1.4d)** are built in a parallel session; the marketplace will link and sitemap them once merged.
- **Blog and CMS pages** (`/blogs/{slug}`, `/pages/{slug}`, `/about-us`, `/faq` …) need media storage (R2, owner account): Later.
- **Legacy transactional URLs** (ticket, multi-ticket and invoice downloads, magic login, signed verification with the instance's `APP_KEY`, resets, distribution links, unsubscribe) resolve by `(instance, legacy id)` and need the ELT id maps (M2.x). The `legacy_redirects` table and proxy lookup are ready for the static part; the loader of the real legacy slug list and the top-GSC URL check come with the Phase 0 audit artifacts (Search Console access pending).
- **`public_reader` / `marketplace_writer` database roles** (roadmap §4.3): the projection is written in the org's own RLS transaction and read through SECURITY DEFINER functions, which gives the same isolation without new login roles. Adding the two roles is a runbook change for production; not needed for correctness.
- ~~Org status changes by staff do not emit an event yet~~: M1.3f emits `org.status_changed@1`; the projector drops and rebuilds the org's listings and the marketplace functions check the org's status. Redis write-through of host resolution (today an in-process LRU); Lighthouse ≥ 90 and the Rich Results Test on 20 production pages (need deployed previews).
- Redirect hits are counted per proxy cache miss (60 s per host and path), so they undercount repeated hits.
