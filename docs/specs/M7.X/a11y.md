# Spec: M7.X — Accessibility audit (attendee app and Staff app)

- **Milestone:** M7.x (mobile hardening), the "Accessibility audit" item of `docs/agent-briefs/m7.x.md`
- **Status:** Built (2026-10-15), branch `agent/m7.x`. Tests and fixes in `apps/mobile`, `apps/staff` and `packages/mobile-core`. No server change, no new message key, no new dependency.
- **Risk tags:** none. Visible changes are small: a tick on the chosen row, a 44 pt switch row, scrolling on short state screens.
- **Criteria:** the Accessibility, Styling and Strings rules in `docs/agent-briefs/mobile-common.md`.

## 1. Goal
Every screen in both apps meets the rules: a role and a name on every control, 44 pt targets, text that can grow to the largest system size, right-to-left layout, and no meaning carried by colour alone. What can be proven in Jest is proven by a test that stays in CI. What only a phone can show is listed in section 7 as "device pass".

## 2. Method
Four layers. Each one fails the build when a rule breaks.

| Layer | What it does | Files |
|---|---|---|
| **Static scan** | Parses every source file with the TypeScript compiler (never a text search, so comments, types and strings are not mistaken for styles). Fails on: `left`/`right`/`margin*Left`/`padding*Right`/`border*Left`/`borderTopLeftRadius`-style keys in a style; `textAlign` left/right; `row-reverse`; a fixed `writingDirection`; `allowFontScaling={false}`; `maxFontSizeMultiplier` under 1.5; `adjustsFontSizeToFit`; `numberOfLines` (except the visible height of a multiline field); a Pressable, Touchable or Switch without `accessibilityRole` and `accessibilityLabel`; a `Text` with `onPress`; a TextInput without a label; an Image without alt text; a kit `Field` with neither `textContentType` nor `autoComplete`; a raw Pressable, TextInput or Switch in a route file (screens must use the kit); a colour literal or colour name outside the theme; an arrow or chevron character in text. | `packages/mobile-core/tests/support/a11y-scan.ts`, run by `apps/mobile/tests/a11y-static.test.ts` and `apps/staff/tests/a11y-static.test.ts` |
| **Rendered audit** | Renders every screen state with React Native Testing Library, in English and in Arabic (right to left), with `PixelRatio.getFontScale` and `useWindowDimensions` at 2.0, and walks the whole tree. See the rules below. Staff door tools also run on a 1024 pt iPad width. | `packages/mobile-core/tests/support/a11y-audit.ts`, run by `apps/mobile/tests/a11y-screens.test.tsx` and `apps/staff/tests/a11y-screens.test.tsx` |
| **Self-tests** | Each rule is broken on purpose, to prove the audit and the scan can fail. | `packages/mobile-core/tests/a11y-audit.test.tsx`, `packages/mobile-core/tests/a11y-scan.test.ts` |
| **Existing tests** | The earlier partial audits stay: the tab bar and sign-in screens in `accessibility.test.tsx`, the Tickets helper in `tickets-a11y-audit.test.tsx`, the Staff kit in `ui-kit.test.tsx`, the verdict screens in `tests/scan/`. | unchanged |

**Rules of the rendered audit** (every host element in the tree):
1. A control is anything with `onPress`/`onClick`, a TextInput, a switch, or a role of button, link, switch, checkbox, tab, radio or search. It needs a non-empty accessible name (label, or the text inside it) and, unless it is a text field, an `accessibilityRole`.
2. Its flattened style has `minHeight` or `height` of at least 44, counting `hitSlop`. An icon-only control also needs 44 in width. A switch needs a 44 pt row around it.
3. A radio, checkbox or tab says whether it is checked or selected.
4. No ancestor with `importantForAccessibility="no-hide-descendants"` hides a control. Images have alt text or are marked decorative. A `Modal` sets `accessibilityViewIsModal`.
5. The error under a text field is in the field's hint, so it is read with the field, and is itself an alert or a live region.
6. Text can grow: no `allowFontScaling={false}`, no cap under 1.5, no fixed `height` around text.
7. The screen has a scroll container (or says why not).
8. Screens with a title have a header role. Scenarios that expect an announcement (an error, a result) assert that an alert or live region carries that text.
9. Arabic: the root has `direction: rtl`, no `{` placeholder leaks into a name, and at least one control name is Arabic script.

Jest has no layout engine. "Fits at the largest size" is therefore proven through its causes (rules 6 and 7, and the static scan), and how it looks is a device pass.

## 5. Decisions
- **Caps of 1.5 or more are allowed.** Two exist: the short ticket code (1.6) and the Staff stat value (1.6). Both are one short number on a card; the label next to each still scales without a cap.
- **Door-tool titles are the navigation header's.** The rendered audit does not ask for an in-screen header on those screens (`app/tools/_layout.tsx` sets the titles).
- **One documented exception to "screens use the kit":** the manual ticket-code field (`scan/ui/manual-entry.tsx`) turns autofill and keyboard learning off and uses large capitals; the kit's field has neither. It still has a label, hint, announced error and 48 pt.
- Components inside a screen folder (an event card, a ticket card, a pass row) may build their own Pressable; the scan and the rendered audit check each one for role, name and size.

## 7. Device pass
Only a phone can confirm these. The device pass runs them, with the Maestro flows in `.maestro/`.

| Check | Why Jest cannot show it |
|---|---|
| VoiceOver (iOS) and TalkBack (Android) read each screen in a sensible order and say the same as the labels | the real speech engine and focus order |
| Real announcements: an error under a field, "order confirmed", the scan verdict, the offline banner | live regions and `alert` behave per platform |
| Largest accessibility sizes on iOS (AX5) and Android (font 200 % and display size largest): nothing clipped or overlapping on a 4.7" and a 6.7" phone, and on an iPad for Staff | no layout engine in Jest |
| Arabic on a real device: tab bar, back gesture, QR screen, scan screen mirror correctly | the native direction switch |
| Verdict sound and haptic at the door: audible with the ringer off, three tones tell apart | audio and haptics hardware |
| Torch control and camera focus in the scanner | camera hardware |
| Push banner stays 6 s then goes: decide with a screen-reader user whether it needs to stay longer when VoiceOver or TalkBack is on | a product decision to test with people |
| Switch Control and keyboard focus on iPad (Staff) | input hardware |
| Contrast of verdict colours in direct sun | environment |
