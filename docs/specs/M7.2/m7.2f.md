# Spec: M7.2f — Browse and checkout API

- **Milestone:** M7.2f (Phase 7 plan `docs/plans/mobile.md`, decision P7-7)
- **Status:** Built (2026-10-14). Server only: no app code, no real Stripe call (the fake provider throughout; `PAYMENTS_PROVIDER=stripe` was never set).
- **Risk tags:** `payments`, `mobile-contract`, `db-migration`
- **Related ADRs/decisions:** 0002 (one command model), 0005, 0014 (allowlists), D13 (private events and weddings)

## 1. Goal and users
The attendee app lets a person find events and buy tickets without leaving it. Search reads the public read model only. Buying uses the web's own steps (hold, hosted payment, attach), opened in a secure in-app browser session that returns to the app. What the app cannot finish natively goes to the web checkout; live-stream access is never sold in the app (Apple's in-app-purchase rule, P7-7).

## 2. What was built
**`GET /v1/public/events`** (`searchPublicEvents`, no credential).
- Filters: `q` (name, tagline, venue, city, organizer), `category` (platform key), `organizer` (slug), `from`/`to` (a date means a UTC day, `to` included; or an instant), and `lat`+`lng`+`radiusKm` (default 25, at most 500). Soonest first, or nearest first with a point; `distanceKm` per result.
- **Keyset paging:** `nextCursor` is the last row's sort key and slug (`[time, iso, slug]` or `[distance, km, slug]`, base64url). A new event never shifts a page; a cursor from the other ordering is a 400, never misread.
- Source: `marketplace.search_public_events` (SECURITY DEFINER, `search_path = pg_catalog`): marketplace rows of live (active or limited) orgs from `public_listings`, never `wedding`, still running. Private and unlisted events are not in `public_listings` at all; weddings and orgs that did not opt in are excluded by the projection and again by the function (D13). It does not use the Meilisearch index, so it works in production before the owner's search account exists, and keyset paging is exact. The existing web search is unchanged.
- Allowlisted result (`PublicEventSummary`): slug, name, tagline, profile, category, status, timezone, starts/ends, venue name, city, country, currency, price range, `organizer {slug, name}`, `distanceKm`, `url`. No ids. 60 searches a minute per client (`RATE_LIMITS.search`), `Cache-Control: public, max-age=30`.

**`POST /v1/public/events/{slug}/checkout`** (`startAppCheckout`; the `/me` scope: a user bearer session with a verified email; API keys are 401).
- **Same steps as `checkoutAction`:** `startCheckoutTx` (hold, all-in pricing, fee snapshot, promo/coupon/credit codes, per-pass limits, sales windows), `createPayment` on the deployment's provider (idempotency key `order:{id}:1`, as the web), `attachPaymentCommand` (hold extended 5 minutes). The command is `orders.startAppCheckout` (`startAppCheckoutCommand`): it runs `startCheckoutTx` unchanged.
- **Buyer:** the session's verified email (it is what finds the person's tickets afterwards), name from the body or the account.
- **Returns** `{action, orderId, paymentUrl, expiresAt, webUrl, webReason}`: `pay` (201, open `paymentUrl`), `paid` (201, a free cart, tickets issued), `web` (200, nothing held). The hosted page returns to **universal links on the web host** the app claims (`/events/*` is in the app-link allowlist): `{web}/events/{slug}?checkout=return&order={orderId}` on completion and `…checkout=cancelled…` on cancel. `CreatePaymentInput` gained an optional `cancelUrl` (Stripe's `cancel_url`; the fake page carries it as `cancel`); without it both links are the return link as before. The links carry no secret (no manage token).
- **Idempotency (required `Idempotency-Key`):** the start is the kernel's idempotent command, so the order is created and the key stored in one transaction. A retry returns the stored order, re-asks the provider for the same payment (deterministic per order), attaches it only if the order has none, and reads the order's current expiry. A retry after the hold lapsed is `409 invalid_state`, `details.reason: hold_expired`. The same key with another cart is `422 idempotency_key_reused`. The stored result has **no manage token**, and the pre-checkout risk rules run inside the command so they stay out of the fingerprint (a retry must replay, not fail because the buyer's order count grew).
- **Rules and limits as the web:** the M1.14 `checkoutStart` policy (per signed-in person standing in for the device cookie, plus the shared IP ceiling), `429` with `Retry-After`; the M1.6e risk rules (block ⇒ `403 forbidden`, `details.reason: risk_blocked`, no rule names, and `order.checkout_blocked` is recorded for the organizer; review ⇒ `riskReview` on the order); the org kill switch and suspension (`invalid_state`, `org_suspended`). Private events are `404` (access codes are web-only).
- **Web checkout for carts the app cannot finish** (`action: web`, nothing held, `webUrl` = the event page with `utm_source=yayatoh-app&utm_medium=app` and `date` for a multi-date event): `webReason` is `checkout_questions` (the event publishes questions), `seat_selection` (a pass sold by seat), `registration` (the event sells through registration types: approvals, groups, guests), `transfer_fee` (a pass whose holders pay a transfer fee), `choose_your_amount` (a donation pass). First match in that order of precedence: registration, seats, questions, transfer fee, amount.
- **Virtual access (P7-7):** a cart with a pass that gives access to a stream (`virtual` or `both`; every pass of an online event unless the organizer chose otherwise) is refused as a whole: `409 invalid_state`, `details {reason: 'buy_on_web', webUrl, ticketTypeIds}`. In-person passes of a hybrid event are bought normally.
- `/v1` additions only: `searchPublicEvents`, `startAppCheckout`; schemas `PublicEventPage`, `PublicEventSummary`, `AppCheckoutRequest`, `AppCheckoutResult`, `AppCheckoutAction`, `AppCheckoutWebReason`. `apps/api/openapi.json`, the SDK schema and the automation apps are regenerated; `pnpm contracts:check` is clean; a structural diff shows no existing operation or schema changed (oasdiff itself runs in CI).
- The fake payment page (dev, preview, CI only) now follows a return link that is a universal link of the apps (`fakeReturnTarget`), so a device pass can land in the app; any other host still goes home.

**Module additions (public, server-side, org taken from the event):** `marketplace.searchPublicEvents`; `ticketing.transferFeeTicketTypeIds`; `seating.seatedTicketTypeIds`; `virtual.streamingTicketTypeIds`; `orders.startAppCheckoutCommand`/`AppCheckoutInput`/`checkoutRiskSignalsTx`; `orderPaymentStateTx` also returns `expiresAt`. `api-v1` now depends on `forms`, `marketplace`, `registration` (moved from dev) and `virtual`; the M1.14 limiter factory moved to `platform-limiter.ts` (the portal sign-in uses it as before). New `V1Deps.checkoutLimiter`.

## 3. Migration (`0174_public_event_search.sql`, to be renumbered at merge)
Custom (`drizzle-kit generate --custom`): no table changes. **All hand-written** (`-- hand-written: begin/end`): `marketplace.search_public_events(...)`, SECURITY DEFINER, `search_path = pg_catalog`, `REVOKE ALL … FROM PUBLIC`, `GRANT EXECUTE … TO app_user`. The `_journal.json` entry and `0174_snapshot.json` are generated.

## 4. Not yet / Later
- Native payment sheet with Apple Pay and Google Pay (P7-7 later). Waitlist offers, access codes and sales-channel codes are web-only; the app has no cookie for them.
- Seat selection and best available in the app (P7-12 keeps interactive seat selection out of Phase 7).
- The pre-checkout country rule is not applied (the app sends no geo header); velocity and payment-failure rules are.
- Search has no facets or "when" presets; the web search is unchanged. Free-text search is `ILIKE` (no typo tolerance); a later change can put it on the Meilisearch index once the owner's account exists, keeping the same contract.
- `url` of a result is the tenant's canonical host when the org runs a tenant site, else the web base URL (`MobileSettings.baseUrls.web`); the app opens it as a link.
- Device pass: the secure in-app browser round trip (open the hosted page, pay on Stripe test mode, land back in the app through the universal link), and the cancel path.
